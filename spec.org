This file governs the repository. =README.org=, =AGENTS.md=, =CLAUDE.md=,
=docs/architecture.md=, =docs/diagrams/*.mmd=, =resources/README.md= and
=scripts/pull-resources.sh= are tangled from it (=make tangle=). When a

Epistemic labels: =[E]= observed in this repository, =[P]= taken from a
cited source, =[H]= hypothesis to be tested, =[I]= author inference.

* Scope

forth-keel builds a Forth system in three layers, each written on top of
the one below, and tests every layer against a fixed oracle corpus:

| Layer   | Lives in            | Written in             | Contents                                             |
|---------+---------------------+------------------------+------------------------------------------------------|
| keel    | =aygp-dr/keel-rs=   | host language (Rust, C) | 13 primitives and the inner interpreter              |
| frames  | =frames/=           | Forth                  | stack words, arithmetic, control flow, compiler, outer interpreter |
| planking| =planking/=         | Forth                  | tagged cells, pairs, symbols, closures, promises, Cheney GC, reader |

The SICP programs in =sea-trials/= are the acceptance tests. The browser
host loads a WebAssembly build of the keel into a ClojureScript
application.

The keel is the only layer written in a host language, and it is the only
one kept in its own repository: https://github.com/aygp-dr/keel-rs. One
copy of the thirteen primitives serves both the native target that M2
gates with =cargo test= and the wasm32 target that M4 gates, so splitting
them would duplicate the kernel. M2 is written in Rust; a C keel stays
possible, and would have to pass the same per-primitive tests. Because the
=[E]= label means "observed in this repository", evidence that lives in
=keel-rs= cannot carry it here — see =docs/review-ledger.org=. [I]

** Non-goals

- Forth-2012 conformance. The Forth-2012 test suite is a reference
  resource, not a gate. [I]
- Floating point, the BLOCK wordset, and multitasking. Tests that need
  them carry =\ layer: x= and stay outside the layered build. [I]
- Performance beyond running the sea-trials within the runner's
  20-second timeout per test. [I]
- SICP 3.4 (concurrency). [I]

* Working rules

These rules bind every contributor, human or agent. =AGENTS.md= and
=CLAUDE.md= restate them; this section is the source.

#+name: working-rules
#+begin_src markdown
- `spec.org` governs. Change it first, then run `gmake tangle`. Never edit
  a derived file by hand.
- A layer uses only the layer below it and its own earlier definitions:
  keel → frames → planking.
- New behaviour starts as `experiments/NNN-name/` with a CONJECTURE.md
  (falsification criteria, labelled claims) and a Makefile whose
  `make test` passes inside the directory. Never reuse or delete a number.
- `sea-trials/` is the oracle. Regenerate an `.out` only for a new or
  changed test, and check every value by hand before committing.
- Before claiming done: `gmake test`, `gmake docs`, `gmake tangle-check`.
  Zero findings; there is no warning tier.
- Commits are conventional, one logical step each, with a git note that
  has a Timeline (including failures) and a Reproduction (command,
  output, cell).
- Deferred or suspected-wrong work goes in an issue that names the
  trigger forcing the revisit, not in a source comment.
- A deviation from these rules is allowed only when declared in the
  commit message and in docs/review-ledger.org.
#+end_src

** Memory map

One linear, byte-addressed memory. Region boundaries are host
constants; every region is cell-aligned. The heap is split into two
semispaces for the copying collector. [H]

** Inner and outer interpreter

The keel runs threaded code (=NEXT=). Frames implement the outer
interpreter, which switches between interpreting and compiling on
=state=. [P] (standard Forth model)

#+name: d-interpreter-states
#+begin_src mermaid :tangle docs/diagrams/04-interpreter-states.mmd
stateDiagram-v2
  [*] --> ReadToken
  ReadToken --> Lookup: token parsed
  ReadToken --> Refill: input empty
  Refill --> ReadToken: line read
  Refill --> [*]: end of input
  Lookup --> Execute: found, state=0 or immediate
  Lookup --> Compile: found, state=1, not immediate
  Lookup --> Number: not found
  Number --> PushLiteral: parsed, state=0
  Number --> CompileLiteral: parsed, state=1
  Number --> Error: not a number
  Execute --> ReadToken
  Compile --> ReadToken
  PushLiteral --> ReadToken
  CompileLiteral --> ReadToken
  Error --> ReadToken: reset stacks, state=0
#+end_src

** Object layout (planking)

A cell with low bit 0 is a fixnum (value shifted left by one). A cell
with low bit 1 is an object reference (address + 1); the object's first
cell is a type header. During collection, a from-space object is
overwritten with a forwarding header. [E] for fixnum and pair in
experiment 002; [H] for the rest.

#+name: d-object-layout
#+begin_src mermaid :tangle docs/diagrams/05-object-layout.mmd

    low bit 1: object addr+1

    header = t-pair

    cdr : Cell

  class Symbol {
    header = t-symbol

    chars
  }
  class Closure {

    env : Cell
  }
  class Promise {
    header = t-promise
    forced flag
    thunk or value : Cell
  }

    header = t-forward
    new address
  }
  Cell --> Pair
  Cell --> Symbol
  Cell --> Closure
  Cell --> Promise
  Pair ..> Forward : during GC
#+end_src

** Garbage collection

Cheney's algorithm: copy the roots, then scan to-space with one pointer
while another marks the end of copied data. The scan finishes when the
two pointers meet. Roots are the data stack, the return stack, and
global cells registered with =root,=. [P] (Cheney 1970; SICP 5.3.2)

#+name: d-cheney-gc
#+begin_src mermaid :tangle docs/diagrams/06-cheney-gc.mmd
sequenceDiagram
  participant M as mutator
  participant A as allocator
  participant C as collector
  participant T as to-space
  M->>A: cons (needs 3 cells)
  A->>A: free + 3 > limit?
  A->>C: collect
  C->>C: swap from-space and to-space
  loop each root (data stack, return stack, globals)
    C->>T: copy object, leave forward in from-space
  end
  loop scan < free
    C->>T: for each field: copy referent or follow forward
  end
  C-->>A: free pointer reset to end of copied data
  A-->>M: new pair
#+end_src

# Resources

Run `scripts/pull-resources.sh` on a machine with general web access.
Git sources are cloned into `resources/vendor/<key>` at the commit pinned
in `spec.org`; web pages are saved as `resources/vendor/<key>.html`.
`resources/vendor/` is not tracked.

The table of sources, pins, and uses is in `spec.org`, section Resources.
One entry there, `cheney-1970`, is a citation rather than a file: its DOI
resolves to the ACM digital library, which refuses automated requests, so
the script does not try to fetch it.
#+end_src

#+begin_src sh :tangle scripts/pull-resources.sh :shebang "#!/usr/bin/env bash"
# Derived from spec.org @ v0.1. The spec governs; if this file disagrees with it, this file is the bug.
# Pull reference sources into resources/vendor/. Idempotent: existing clones are re-pinned, pages re-fetched.
set -euo pipefail
cd "$(dirname "$0")/.."
dest=resources/vendor
mkdir -p "$dest"
pin() {  # key url commit
  if [ ! -d "$dest/$1/.git" ]; then git clone -q "$2" "$dest/$1"; fi
  git -C "$dest/$1" fetch -q origin "$3" 2>/dev/null || git -C "$dest/$1" fetch -q origin
  git -C "$dest/$1" -c advice.detachedHead=false checkout -q "$3"
  echo "git  $1 @ $(git -C "$dest/$1" rev-parse --short HEAD)"
}
page() {  # key url
  if curl -fsSL --max-time 180 -o "$dest/$1.html" "$2"; then echo "web  $1 ($(wc -c < "$dest/$1.html") bytes)"
  else rm -f "$dest/$1.html"; echo "web  $1 FAILED: $2" >&2; return 1; fi

* Debug toolchain

R-H-01 makes gforth 0.7.3 the reference host, so the oracle and the
debugger are the same program. A gforth built for debugging is therefore
part of the toolchain, not a personal preference. [I]

Build it from the GNU source release, outside the repository, so that
=gforth= on =PATH= is the engine with debug information and its sources
stay where gdb can find them:

#+begin_src sh
CC=gcc CFLAGS="-g3 -ggdb3 -O0 -fno-omit-frame-pointer -fno-strict-aliasing -std=gnu99" \
  ./configure --prefix="$HOME/.local/opt/gforth-0.7.3-debug" --with-debug --enable-prof
gmake && gmake gforth-fast && gmake install
#+end_src

=--with-debug= keeps =-g=; =--enable-prof= adds =gforth-prof=, which
reports the primitive sequences a program executes. The default =all=
target does not build =gforth-fast=, which =install= requires, so it is
named explicitly. The engines this produces:

| Engine         | What it is for                                              |
|----------------+-------------------------------------------------------------|
| =gforth=       | the debugging engine: backtraces, and the one gdb attaches to |
| =gforth-fast=  | the optimised engine, for long corpus runs                   |
| =gforth-itc=   | indirect threaded, for comparing dispatch strategies         |
| =gforth-ditc=  | direct threaded, used to bootstrap the image                 |
| =gforth-prof=  | prints frequently occurring primitive sequences              |

A debug build must still reproduce the oracle: =sea-trials/run.sh= has
to pass 29/29 against =.out= files generated by a stock 0.7.3, which is
what shows the build changed no behaviour. [E]

** Debugging in Forth

Reach for these before gdb; they need no special build.

| Word            | What it shows                                              |
|-----------------+------------------------------------------------------------|
| =~~=            | file, line, depth and the stack at that point in a definition |
| backtrace       | printed automatically when a throw escapes, naming the Forth words |
| =see=           | decompiles a definition                                     |
| =dbg=           | single-steps a definition                                   |

** Debugging in gdb

[[file:tools/gforth.gdb][tools/gforth.gdb]] adds commands that speak in Forth terms:

#+begin_src sh
gdb -x tools/gforth.gdb --args gforth yourfile.fs -e bye
#+end_src

- =fstart= runs to the point where the primitive table exists.
- =fbreak <word>= breaks on a Forth primitive by name, resolving it
  through =prim_names[]= to its label address in =vm_prims[]=. It takes
  a condition, so =fbreak + if sp[0]==3= stops on one specific addition.
- =fstack= and =frstack= print cells from =sp= and =rp=.
- =fprims= lists the primitives gforth was built with.

Each primitive is a label inside one =gforth_engine= function, generated
into =engine/prim.i=, so a primitive breakpoint is an address rather
than a function name. Where the top of stack lives depends on the build:
with the flags above it is in memory at =sp[0]=, while gforth's
=-DDEBUG= engine caches it in a separate =spTOS=. =-DDEBUG= also traces
every primitive with its ip, depth and stack to stderr, which is
unusable as a default and pollutes any run whose output is compared.
=VM_DEBUG=, which appears in the generated =prim.i=, cannot be used: it
references =vm_debug= and =vm_out=, which gforth 0.7.3 never declares. [E]

Documentation for all of this is in [[file:docs/debugging.md][docs/debugging.md]].

A Forth system built in three layers, each written on top of the one
below, and tested against a fixed oracle corpus of SICP programs. A
layer uses only the layer below it and its own earlier definitions.

,* Layers

| Layer    | Written in              | Contents                                                            |
|----------+-------------------------+---------------------------------------------------------------------|
| keel     | host language (Rust, C) | 13 primitives and the inner interpreter                             |
| frames   | Forth                   | stack words, arithmetic, control flow, compiler, outer interpreter  |
| planking | Forth                   | tagged cells, pairs, symbols, closures, promises, Cheney GC, reader |

The keel provides exactly =@ ! sp@ rp@ 0= + nand exit key emit execute
um* um/mod=. =nand= is the only logical primitive: =invert=, =and=, =or=
and =negate= are all derived from it in Forth. =sp@= yields the address
holding the former top of stack, which is what makes =dup= definable as
=sp@ @=. Cells are at least 32 bits and the corpus assumes no more than
32, so results match on a 32-bit host.

# gforth helpers for gdb. Load them with:
#   gdb -x tools/gforth.gdb --args gforth yourfile.fs -e bye
# then: fstart, fbreak +, fstack, frstack, fprims.
set pagination off
set print pretty on

python
import gdb

# Length of prim_names[] in gforth 0.7.3. Reading stops early if the build
# has fewer, so an overestimate is harmless.
PRIM_COUNT = 334


def _prim_names():
    """Map each primitive name to its index in prim_names[]."""
    names = gdb.parse_and_eval("prim_names")
    out = {}
    for i in range(PRIM_COUNT):
        try:
            out[names[i].string()] = i
        except gdb.error:
            break
    return out


def _cells(pointer, count):
    """Yield (index, value) for count cells from pointer, stopping at unmapped memory."""
    for i in range(count):
        try:
            yield i, int(pointer[i])
        except gdb.MemoryError:
            return


class Fstart(gdb.Command):
    """Run until gforth's primitive table exists, so fbreak can resolve names.

vm_prims[] is filled in only after the image is loaded, so resolving a
primitive before that reads uninitialised memory."""

    def __init__(self):
        super(Fstart, self).__init__("fstart", gdb.COMMAND_RUNNING)

    def invoke(self, arg, from_tty):
        gdb.execute("tbreak gforth_go")
        gdb.execute("run " + arg)


class Fbreak(gdb.Command):
    """Break on a Forth primitive by name: fbreak <word> [if <condition>]

Resolves the word through prim_names[] to its label address in vm_prims[].
Every primitive is a label inside the single gforth_engine function, so this
is an address breakpoint, not a function one. Run fstart first. A condition
may follow, which is how to stop on one specific case:

    fbreak + if sp[0]==3 && sp[1]==2"""

    def __init__(self):
        super(Fbreak, self).__init__("fbreak", gdb.COMMAND_BREAKPOINTS)

    def invoke(self, arg, from_tty):
        parts = arg.strip().split(None, 1)
        if not parts:
            print("usage: fbreak <forth-word> [if <condition>]")
            return
        name, cond = parts[0], (parts[1] if len(parts) > 1 else "")
        index = _prim_names().get(name)
        if index is None:
            print('fbreak: "%s" is not a primitive in this build; try fprims' % name)
            return
        try:
            addr = int(gdb.parse_and_eval("vm_prims")[index])
        except gdb.error as e:
            print("fbreak: cannot read vm_prims (%s); run fstart first" % e)
            return
        gdb.execute(("break *%d %s" % (addr, cond)).strip())
        print('fbreak: "%s" is primitive %d at %#x' % (name, index, addr))


class Fstack(gdb.Command):
    """Print cells from the data stack pointer: fstack [count]

sp[0] is the top of stack in a build made with the spec's debug flags. Stop
inside gforth_engine first, for instance at an fbreak breakpoint."""

    def __init__(self):
        super(Fstack, self).__init__("fstack", gdb.COMMAND_DATA)

    def invoke(self, arg, from_tty):
        count = int(arg) if arg.strip() else 8
        try:
            sp = gdb.selected_frame().read_var("sp")
        except (gdb.error, ValueError):
            print("fstack: no sp in scope; stop inside gforth_engine first")
            return
        print("sp = %#x" % int(sp))
        for i, v in _cells(sp, count):
            print("  sp[%d] = %d%s" % (i, v, "   <- top" if i == 0 else ""))


class Frstack(gdb.Command):
    """Print cells from the return stack pointer: frstack [count]"""

    def __init__(self):
        super(Frstack, self).__init__("frstack", gdb.COMMAND_DATA)

    def invoke(self, arg, from_tty):
        count = int(arg) if arg.strip() else 8
        try:
            rp = gdb.selected_frame().read_var("rp")
        except (gdb.error, ValueError):
            print("frstack: no rp in scope; stop inside gforth_engine first")
            return
        print("rp = %#x" % int(rp))
        for i, v in _cells(rp, count):
            print("  rp[%d] = %#x%s" % (i, v, "   <- top" if i == 0 else ""))


class Fprims(gdb.Command):
    """List the primitives this gforth was built with: fprims [substring]"""

    def __init__(self):
        super(Fprims, self).__init__("fprims", gdb.COMMAND_DATA)

    def invoke(self, arg, from_tty):
        pattern = arg.strip()
        try:
            names = _prim_names()
        except gdb.error as e:
            print("fprims: cannot read prim_names (%s)" % e)
            return
        for name, index in sorted(names.items(), key=lambda kv: kv[1]):
            if not pattern or pattern in name:
                print("%4d  %s" % (index, name))

# Debugging forth-keel

gforth 0.7.3 is both the oracle and the debugger (R-H-01), so one engine
answers "what should this print?" and "why did it print that?". The build
flags, the engines and the gdb commands are specified in
[../spec.org](../spec.org) under *Debug toolchain*; this file is how to use
them.

## Start in Forth, not in gdb

Most questions are answered without a debugger at all.

| You want | Do this |
|---|---|
| the stack at a point inside a definition | put `~~` there: it prints file, line, depth and the stack |
| to know which word threw | nothing — a throw that escapes prints a backtrace naming the Forth words |
| to read back what you compiled | `see word` |
| to step a definition | `dbg word` |

```
$ gforth -e ': inner 1 0 / ;' -e ': outer inner ;' -e 'outer'
*OS command line*:-1: Division by zero
>>>outer<<<
Backtrace:
$277B4E6572F0 /
$277B4E657330 inner
```

## Then gdb, in Forth terms

```sh
gdb -x tools/gforth.gdb --args gforth yourfile.fs -e bye
```

- `fstart` — run to where the primitive table exists. Do this first:
  `vm_prims[]` is populated only after the image loads, so resolving a
  primitive earlier reads uninitialised memory.
- `fbreak <word>` — break on a Forth primitive by name, with an optional
  condition. This is the sharpest tool here: it stops on one *particular*
  execution of a word, by what is on the Forth stack.
- `fstack` / `frstack` — cells from `sp` / `rp`. `sp[0]` is the top.
- `fprims` — every primitive in this build, with its index.

Stopping on one specific addition:

```
(gdb) fstart
(gdb) fbreak + if sp[0]==3 && sp[1]==2
fbreak: "+" is primitive 53 at 0x405867
(gdb) continue
Breakpoint 2, gforth_engine (...) at engine/prim.i:2896
(gdb) fstack 2
sp = 0x800826ff0
  sp[0] = 3   <- top
  sp[1] = 2
```

## Why a primitive is an address, not a function

gforth compiles every primitive as a label inside one `gforth_engine`
function, generated into `engine/prim.i`, and dispatches between them with
computed gotos. So there is no `plus()` to break on; `fbreak` resolves the
name through `prim_names[]` to the label address recorded in `vm_prims[]`.
`engine/prim.i` is real, compiled source with debug information, so
`list`, `info locals` and line breakpoints all work inside it.

## Where the top of stack lives

It depends on the build. With the spec's debug flags the top of stack is in
memory at `sp[0]`, which is what makes `fbreak + if sp[0]==3` possible.
gforth's `-DDEBUG` engine instead caches it in a separate `spTOS` variable,
and computes depth against `sp0` with an offset — so a helper written for
one build misreads the other. `fstack` therefore prints cells from `sp`
rather than claiming a depth.

## Engines

| Engine | Use |
|---|---|
| `gforth` | debugging: backtraces, and what gdb attaches to |
| `gforth-fast` | long corpus runs |
| `gforth-itc` | indirect threaded, for comparing dispatch |
| `gforth-ditc` | direct threaded, bootstraps the image |
| `gforth-prof` | prints frequently occurring primitive sequences |

`gforth-prof` is the one to reach for before optimising anything in
`frames`: it reports which primitive sequences actually run, which is the
evidence for adding a superinstruction rather than a guess.

## Two traps

- **`-DDEBUG` pollutes output.** It traces every primitive with its ip,
  depth and stack to stderr. The sea-trials compare output, so a `-DDEBUG`
  engine fails them all. Build it separately if you want it; never make it
  the engine on `PATH`.
- **`VM_DEBUG` does not compile.** It appears in the generated `prim.i`,
  but gforth 0.7.3 never declares `vm_debug`, `vm_out` or `printarg_n`, so
  that branch is dead. Do not reach for it.

## The debug build must still be the oracle

Changing build flags must not change behaviour. The check is the corpus:

```sh
sea-trials/run.sh        # must be 29/29 against .out files from a stock 0.7.3
```

A debug engine that fails a sea-trial is not a debugging aid, it is a
second bug.
